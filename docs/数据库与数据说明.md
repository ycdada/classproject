# 数据库与数据说明

## 1. 说明

本文档说明系统运行过程中使用的数据库、课程资料、题库、向量索引、上传文件和对话检查点的位置，以及数据导入、备份和恢复方法。

## 2. 数据目录

```text
backend/
├── data/
│   ├── ds_teaching.db       # SQLite 结构化业务数据库
│   └── chroma/              # ChromaDB 向量索引目录
├── uploads/                 # 已上传并解析的课程资料
├── checkpoints.db           # 教学助手对话状态检查点
└── .env                     # 本机配置和 API 密钥，不提交

数据结构资料/                 # 项目附带课程资料和演示材料
```

当前项目中的课程资料包括绪论、线性表、栈和队列、树、图、查找、排序、矩阵和森林等 PDF 或 PPTX 文件。

## 3. SQLite 数据库

默认位置：

```text
backend/data/ds_teaching.db
```

应用启动时会自动创建不存在的数据表。数据库使用 SQLAlchemy 异步访问，默认连接配置为：

```text
sqlite+aiosqlite:///./data/ds_teaching.db
```

### 3.1 主要数据表

| 表名 | 用途 | 主要内容 |
|---|---|---|
| `materials` | 课程材料 | 文件名、类型、路径、解析文本、章节和页数 |
| `knowledge_nodes` | 知识树 | 章、节、知识点、父子关系、定义和教学重点 |
| `questions` | 题库 | 题型、难度、题干、选项、答案、解析和知识点 |
| `exam_scopes` | 考查范围 | 出卷需求和范围确认状态 |
| `exam_scope_nodes` | 范围节点 | 范围树、纳入状态和排序 |
| `question_drafts` | 题目草稿 | 待审核题目及审核状态 |
| `exams` | 试卷 | 标题、总分、时长、组卷需求和知识范围快照 |
| `exam_questions` | 试卷题目关系 | 试卷、题目、分值和题目顺序 |

### 3.2 关键数据关系

```text
课程材料 1 ─── N 知识节点
课程材料 1 ─── N 题目
考查范围 1 ─── N 范围节点
考查范围 1 ─── N 题目草稿
试卷 1 ─── N 试卷题目 N ─── 1 题目
```

### 3.3 状态规则

- 考查范围：`proposed` → `confirmed`。
- 题目草稿：`pending` → `accepted` 或 `rejected`。
- 试卷：默认创建为 `draft`，后续可以进入审核或导出状态。
- 只有确认后的考查范围才能用于组卷。
- 只有接受的题目草稿才能进入题库。

## 4. 课程材料

### 4.1 材料目录

课程原始资料放在：

```text
数据结构资料/
```

用户通过网页上传的文件保存在：

```text
backend/uploads/
```

两处资料的用途不同：`数据结构资料/`用于项目演示和初始素材，`backend/uploads/`用于系统运行时保存教师上传的材料。

### 4.2 支持格式

系统支持：

- PDF：使用 PyMuPDF 读取文本。
- PPTX：使用 python-pptx 读取幻灯片文字。
- DOCX：使用 python-docx 读取段落和表格内容。
- MD：直接读取 Markdown 文本。

解析后的文本保存到 `materials.content_md`，用于材料详情展示、知识树提取和题目提取。

### 4.3 材料元数据

每条材料记录包含：

- 文件名和文件类型。
- 实际保存路径。
- 材料类型：讲义、课件、教学大纲或其他。
- 所属章节。
- 解析文本。
- 页数或幻灯片数量。
- 上传时间。

## 5. 题库数据

### 5.1 题目字段

题目至少需要以下字段：

| 字段 | 要求 |
|---|---|
| `type` | `choice`、`fill`、`tf`、`short_answer` 或 `code` |
| `difficulty` | 1 到 5 的整数 |
| `content` | 题干，必填 |
| `answer` | 答案，必填 |
| `knowledge_point_ids` | 关联知识点 ID 列表，可为空 |
| `chapter` | 所属章节，可为空 |
| `options` | 选择题选项，可为空 |
| `explanation` | 题目解析，可为空 |
| `source` | 题目来源，默认 `manual` |

### 5.2 JSON 导入示例

```json
[
  {
    "type": "choice",
    "difficulty": 2,
    "knowledge_point_ids": [],
    "chapter": "第三章 栈和队列",
    "content": "下列哪种结构满足先进后出的特点？",
    "options": {
      "A": "队列",
      "B": "栈",
      "C": "数组",
      "D": "图"
    },
    "answer": "B",
    "explanation": "栈遵循后进先出原则。",
    "source": "manual"
  }
]
```

### 5.3 XLSX 导入

XLSX 第一行作为字段名，后续每行作为一道题目。建议列名使用：

```text
type, difficulty, knowledge_point_ids, chapter, content,
options, answer, explanation, source
```

其中：

- `knowledge_point_ids` 使用逗号分隔。
- `options` 使用竖线分隔。
- `tags` 如有使用逗号分隔。
- `difficulty` 必须是 1 到 5 的整数。

### 5.4 题库导入方式

启动系统后，进入“题库”页面，选择“批量导入”，上传 JSON 或 XLSX 文件。也可以调用：

```text
POST /api/questions/batch-import
```

导入后应检查题型、难度、答案和章节是否正确，再进行向量索引。

## 6. 向量数据

向量数据库目录：

```text
backend/data/chroma/
```

系统使用本地中文向量模型将题目或查询文本转换为向量，并在 ChromaDB 中保存索引。`questions.embedding_id` 保存题目对应的向量 ID。

题目发生批量变化后，可以调用：

```text
POST /api/questions/embed-all
```

重新建立题库索引。首次运行可能需要下载本地 embedding 模型，耗时取决于网络和电脑性能。

## 7. 教学助手数据

教学助手的 LangGraph 检查点默认保存在：

```text
backend/checkpoints.db
```

该文件用于保存 `thread_id` 对应的对话流程状态，使范围确认和试卷审核暂停后能够继续执行。删除该文件会清除本机已有的对话检查点，但不会删除 SQLite 题库和试卷数据。

## 8. 数据备份

### 8.1 需要备份的内容

完整备份建议包含：

```text
backend/data/ds_teaching.db
backend/data/chroma/
backend/uploads/
backend/checkpoints.db
```

如果只需要备份结构化业务数据，至少备份 `backend/data/ds_teaching.db`。如果需要完整恢复语义检索，还必须备份 `backend/data/chroma/`。

### 8.2 PowerShell 备份示例

```powershell
cd D:\pjt\classproject
$backup = "D:\pjt\classproject-backup"
New-Item -ItemType Directory -Force $backup | Out-Null
Copy-Item -Recurse -Force backend\data $backup\data
Copy-Item -Recurse -Force backend\uploads $backup\uploads
Copy-Item -Force backend\checkpoints.db $backup\checkpoints.db
```

备份路径应放在项目目录之外，避免被 Git 误提交。

## 9. 数据恢复

恢复前先停止后端服务，并保留当前数据的临时备份。确认备份内容后，将备份文件复制回对应目录，再启动后端。

```powershell
cd D:\pjt\classproject
Copy-Item -Recurse -Force D:\pjt\classproject-backup\data backend\data
Copy-Item -Recurse -Force D:\pjt\classproject-backup\uploads backend\uploads
Copy-Item -Force D:\pjt\classproject-backup\checkpoints.db backend\checkpoints.db
```

恢复后检查：

1. `/api/health` 是否返回 `{"status":"ok"}`。
2. 材料列表和题库是否能正常显示。
3. 知识树和试卷详情是否能正常打开。
4. 语义检索是否能返回结果。
5. 教学助手是否能继续已有会话。

## 10. 演示数据建议

建议准备一套稳定的演示数据：

- 3 到 5 份课程材料，覆盖不同文件格式。
- 每个主要章节至少准备若干道题目。
- 包含选择题、判断题、填空题和简答题。
- 至少准备一个题库不足的组卷场景，用于演示题目草稿审核。
- 至少准备一份已生成的试卷，用于演示预览和导出。

演示数据不应包含个人隐私、真实 API 密钥或未经授权的敏感资料。

## 11. 提交注意事项

### 建议提交

- 源代码目录。
- `backend/requirements.txt` 和 `frontend/package.json`。
- `.env.example`，但不包含真实密钥。
- 脱敏后的示例题库或初始化数据。
- 必要的课程资料和项目文档。

### 不建议提交

- `backend/.env`。
- API 密钥和个人账号信息。
- Python `.venv/` 目录。
- 前端 `node_modules/` 目录。
- 临时日志、缓存和未完成的导出文件。
- 未确认版权或包含个人隐私的材料。

## 12. 数据重置说明

重置前必须备份。仅清空数据库不会自动清理上传文件和向量索引；如果需要完全重新开始，应分别处理：

1. `backend/data/ds_teaching.db`。
2. `backend/data/chroma/`。
3. `backend/uploads/`。
4. `backend/checkpoints.db`。

除非明确需要重置演示环境，不要直接删除这些目录或文件。
