# 数据结构智能出卷系统开发文档

## 1. 文档说明

### 1.1 编写目的

本文档用于说明数据结构智能出卷系统的设计思路、项目结构、业务流程、数据结构、接口约定、运行方式和测试方法，为项目开发、部署、演示和后续维护提供统一参考。

### 1.2 系统定位

本系统面向数据结构课程教师，主要解决课程材料整理、知识点维护、题库管理、考查范围确认、智能组卷、题目审核和试卷导出等问题。

### 1.3 使用范围

当前系统提供教师端功能，不包含学生账号、在线答题、自动阅卷、成绩管理和多租户权限体系。

## 2. 需求概述

### 2.1 用户角色

系统当前面向教师用户。教师可以上传课程资料，维护知识树和题库，填写出卷需求，确认考查范围，审核题目草稿，并编辑和导出试卷。

### 2.2 核心业务流程

```text
上传课程材料
      ↓
解析材料并提取知识树
      ↓
维护题库和检索题目
      ↓
填写出卷需求
      ↓
提出考查范围
      ↓
教师调整并确认范围
      ↓
按确认范围组卷
      ↓
生成试卷和待审核题目草稿
      ↓
审核草稿、编辑试卷
      ↓
预览并导出试卷
```

### 2.3 功能需求

#### 课程材料管理

- 支持上传 PDF、PPTX、DOCX 和 Markdown 文件。
- 保存文件名、文件类型、文件路径、材料类型、章节、解析文本和页数。
- 支持材料列表、详情查看和删除。

#### 知识树管理

- 从已解析材料中提取章、节和知识点。
- 知识节点支持定义、关键词、教学重点、解题步骤和来源文本。
- 支持以树形结构展示知识节点。
- 支持手动编辑和删除知识树。

#### 题库管理

- 支持选择题、填空题、判断题、简答题和代码题等题型。
- 支持新增、编辑、删除、分页、关键词查询和条件筛选。
- 支持 JSON 和 XLSX 批量导入。
- 支持从课程材料中提取题目。
- 支持建立向量索引并进行语义搜索。

#### 组卷管理

- 支持设置标题、教学进度、考试范围、重点说明、关联材料、总分、时长、题型分布和难度分布。
- 根据出卷需求提出考查范围。
- 教师可以修改、增加、删除和选择范围节点。
- 只有确认后的范围才能进入组卷流程。
- 优先从题库中选择符合要求的题目。
- 题目不足时生成待审核草稿，并返回缺题信息。

#### 草稿审核

- 支持查看待处理草稿。
- 支持编辑草稿内容、选项、答案、解析和难度。
- 支持接受或拒绝草稿。
- 接受后的草稿转为题库题目，并可建立向量索引。

#### 试卷管理

- 保存试卷标题、总分、时长、组卷需求和知识范围快照。
- 支持试卷列表和详情查看。
- 支持替换题目、修改题目内容、调整分值和顺序。
- 支持重新生成单道题目。
- 支持试卷评估、校验和删除。
- 支持 DOCX、PDF、TXT 和答题卡导出。

#### 教学助手

- 支持课程知识问答。
- 支持语义搜题。
- 支持提出考查范围和辅助组卷。
- 通过 SSE 返回意图、工具调用、范围确认、审核等待、文本和完成事件。

## 5. 后端设计

### 5.1 应用入口

`backend/app/main.py` 创建 FastAPI 应用，注册 CORS，初始化数据库和 ChromaDB，并以 `/api` 为所有业务路由的统一前缀。

健康检查接口：

```text
GET /api/health
返回：{"status": "ok"}
```

### 5.2 路由模块

#### 材料接口 `/api/materials`

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | `/upload` | 上传并解析材料 |
| GET | `/` | 获取材料列表 |
| GET | `/{material_id}` | 获取材料详情和解析内容 |
| DELETE | `/{material_id}` | 删除材料及其文件 |

支持的上传类型：`pptx`、`docx`、`pdf`、`md`。材料解析由 `file_parser.py` 负责。

#### 知识接口 `/api/knowledge`

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | `/extract/{material_id}` | 从材料提取知识树 |
| GET | `/tree/{material_id}` | 获取材料知识树 |
| PUT | `/nodes/{node_id}` | 修改知识节点 |
| DELETE | `/tree/{material_id}` | 删除材料知识树 |

#### 题库接口 `/api/questions`

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | `/search` | 语义检索题目 |
| POST | `/embed-all` | 重建全部题目的向量索引 |
| GET | `/` | 分页和条件查询题目 |
| GET | `/{question_id}` | 查看单道题目 |
| POST | `/` | 新增题目 |
| PUT | `/{question_id}` | 修改题目 |
| DELETE | `/{question_id}` | 删除题目 |
| POST | `/batch-import` | 批量导入 JSON 或 XLSX |
| POST | `/extract/{material_id}` | 从课程材料提取题目 |

#### 考查范围接口 `/api/scopes`

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | `/propose` | 根据出卷需求提出范围 |
| GET | `/{scope_id}` | 获取范围和树结构 |
| PUT | `/{scope_id}/nodes/{node_id}` | 修改范围节点 |
| POST | `/{scope_id}/nodes` | 增加范围节点 |
| DELETE | `/{scope_id}/nodes/{node_id}` | 删除范围节点及子树 |
| POST | `/{scope_id}/confirm` | 确认考查范围 |

范围确认后，节点不允许继续修改、增加或删除。

#### 试卷接口 `/api/exams`

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | `/generate` | 根据已确认范围生成试卷 |
| GET | `/` | 获取试卷列表 |
| GET | `/{exam_id}` | 获取试卷详情 |
| PUT | `/{exam_id}/questions/{eq_id}` | 修改试卷题目、分值或顺序 |
| POST | `/{exam_id}/questions/{eq_id}/regenerate` | 重新生成单题 |
| GET | `/{exam_id}/export` | 导出 DOCX、PDF 或 TXT |
| POST | `/{exam_id}/evaluate` | 评估试卷 |
| POST | `/{exam_id}/verify` | 校验试卷 |
| GET | `/{exam_id}/answer-sheet` | 导出答题卡 |
| DELETE | `/{exam_id}` | 删除试卷 |

`POST /generate` 必须提供已确认的 `scope_id`，否则返回参数错误或范围未确认错误。

#### 草稿接口 `/api/drafts`

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | `/` | 按状态查看题目草稿 |
| PUT | `/{draft_id}` | 修改草稿 |
| POST | `/{draft_id}/accept` | 接受草稿并转入题库 |
| POST | `/{draft_id}/reject` | 拒绝草稿 |

#### 教学助手接口 `/api/chat`

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | `/` | 发送消息或提交审核恢复操作 |

该接口返回 `text/event-stream`。主要事件包括 `intent`、`tool_call`、`scope_pending`、`review_pending`、`text`、`done` 和 `error`。

## 6. 数据库设计

### 6.1 数据库配置

默认数据库：

```text
backend/data/ds_teaching.db
```

应用启动时通过 `Base.metadata.create_all` 创建不存在的表。当前项目使用 SQLite 和 SQLAlchemy 异步访问。

### 6.2 主要数据表

#### `materials` 课程材料表

保存文件名、文件类型、文件路径、材料类型、章节、解析后的 Markdown 内容、页数和上传时间。

#### `knowledge_nodes` 知识节点表

通过 `material_id` 关联材料，通过 `parent_id` 形成树形层级。节点类型包括章、节和知识点，并保存定义、关键词、教学重点、解题步骤和来源文本。

#### `questions` 题目表

保存题型、难度、章节、知识点 ID、题干、选项、答案、解析、来源材料和向量 ID。

#### `exam_scopes` 考查范围表

保存范围状态和出卷需求 JSON。状态包括 `proposed` 和 `confirmed`。

#### `exam_scope_nodes` 范围节点表

保存范围树节点、来源知识节点、父子关系、排序、内容和是否纳入组卷。

#### `question_drafts` 题目草稿表

保存题目草稿内容、难度、知识点、所属范围和审核状态。状态包括 `pending`、`accepted` 和 `rejected`。

#### `exams` 试卷表

保存标题、创建者、状态、总分、时长、出卷需求和知识范围快照。

#### `exam_questions` 试卷题目关联表

保存试卷与题目的关联、单题分值和排序。

### 6.3 数据关系

```text
materials 1 ─── N knowledge_nodes
materials 1 ─── N questions
exam_scopes 1 ─── N exam_scope_nodes
exam_scopes 1 ─── N question_drafts
exams 1 ─── N exam_questions N ─── 1 questions
```

### 6.4 向量数据

ChromaDB 默认保存于：

```text
backend/data/chroma/
```

题目表中的 `embedding_id` 用于关联向量记录。题目新增或接受草稿后可建立向量索引；`POST /api/questions/embed-all` 可根据题库重建索引。

## 7. 核心业务实现

### 7.1 材料解析

`FileParser` 根据扩展名选择对应解析方式：PDF 使用 PyMuPDF，PPTX 使用 python-pptx，DOCX 使用 python-docx，Markdown 直接读取文本。解析结果统一保存为 Markdown 文本，供详情展示、知识提取和题目提取使用。

### 7.2 知识树提取

知识提取服务将材料解析文本提交给大模型，要求返回结构化的章、节和知识点。路由层删除该材料原有知识树后保存新节点，并通过 `parent_id` 和 `sort_order` 恢复层级结构。

### 7.3 题目检索

题目检索支持结构化筛选和语义搜索。结构化筛选使用题型、难度、章节和关键词；语义搜索先将查询文本转换为向量，再从 ChromaDB 返回相似题目，并结合筛选条件限制结果范围。

### 7.4 范围确认

`ScopeBuilder` 根据出卷需求和知识树提出范围，保存为 `proposed` 状态。教师可以调整范围树；确认后状态改为 `confirmed`。试卷生成接口只接受已确认范围，从流程上保证组卷前完成范围审核。

### 7.5 组卷与草稿

`PaperAssembler` 优先从题库选择满足题型、难度、知识点和数量要求的题目。题库不足时调用题目生成服务创建 `QuestionDraft`，返回缺题数量和草稿列表。草稿不直接写入题库或试卷，只有教师接受后才转为正式题目。

### 7.6 教学助手流程

`agent_v2/` 使用 LangGraph 管理对话状态和节点流程，包括意图路由、搜题、知识查询、提出范围、组卷、审核暂停和对话回复。对需要教师确认的范围或试卷，流程通过 interrupt 暂停，收到恢复指令后继续执行。SQLite 检查点保存会话线程状态。

### 7.7 试卷导出

- `docx_export.py`：生成 Word 试卷。
- `exam_export.py`：生成 PDF 和 TXT 试卷。
- `answer_sheet.py`：生成答题卡。

导出时根据试卷题目顺序读取题目内容、选项、答案、解析和分值，并通过 `with_answer` 参数控制是否包含答案和解析。

UPLOAD_DIR=./uploads
CHROMA_PERSIST_DIR=./data/chroma
LOCAL_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5

### 9.3 手工验收流程

1. 上传 PDF 或 PPTX 课程材料。
2. 查看材料详情和解析文本。
3. 提取知识树并检查层级。
4. 新增题目或导入 JSON/XLSX 题库。
5. 按关键词或知识点检索题目。
6. 填写出卷需求并提出范围。
7. 修改范围节点并确认范围。
8. 生成试卷，检查题目数量和缺题草稿。
9. 编辑、接受或拒绝题目草稿。
10. 调整试卷题目、分值和顺序。
11. 分别导出 DOCX、PDF、TXT 和答题卡。
12. 使用教学助手完成一次知识查询和一次搜题。

### 9.4 关键验收规则

- 未确认考查范围时不能生成试卷。
- 待审核草稿不能直接进入题库或试卷。
- 接受草稿后可以在题库中查询到对应题目。
- 删除材料时同步删除材料文件和关联知识树。
- 导出文件应包含正确的标题、题目顺序、分值和总分。
- 未配置 API 密钥时，基础页面和数据库功能仍应能启动；智能功能应返回清晰错误。

## 10. 异常处理与安全要求

### 10.1 接口错误

后端使用 HTTP 状态码表示错误类型：400 表示参数或状态不合法，404 表示资源不存在，409 表示当前状态不允许操作，500 表示解析或外部服务异常。前端应将错误提示展示给教师，不应静默失败。

### 10.2 文件处理

- 上传前检查扩展名。
- 上传文件保存于 `backend/uploads/`。
- 删除材料时同步删除文件。
- 不在日志中输出 API 密钥。
- 对演示数据进行脱敏，避免提交个人信息。

### 10.3 数据备份

需要备份的内容包括：

- `backend/data/ds_teaching.db`
- `backend/data/chroma/`
- `backend/uploads/`
- `backend/checkpoints.db`

重置数据库或删除上传目录前应先复制备份，不要直接清空已有演示数据。

## 11. 已知限制和后续改进

### 已知限制

- 当前没有登录和权限控制。
- 大模型和向量模型依赖外部网络或本地模型环境。
- 课程材料解析结果会受到原始文件排版影响。
- 组卷结果仍需要教师人工检查。
- 当前数据初始化主要依赖应用启动时自动建表，没有完整迁移体系。

### 后续改进方向

- 增加用户登录、角色权限和操作记录。
- 增加数据库迁移和正式部署配置。
- 优化大文件解析、任务队列和进度提示。
- 增加更细的组卷约束和题目去重策略。
- 增加导出模板和更多试卷格式。
- 增加端到端测试、接口文档截图和自动化演示数据初始化。

## 12. 维护约定

- 修改接口时同步更新 Schema、前端类型、API 封装和页面调用。
- 修改数据库模型时同步检查关联服务和测试。
- 修改组卷规则时必须验证范围确认和草稿审核流程。
- 提交前运行后端测试和前端构建。
- 配置密钥只放在本地 `.env`，不写入代码、文档、日志或提交记录。
